# レビュー・実装報告ルール

全レビュー担当と test_runner は、指揮官へ次の形式で報告する。実在しないテスト結果や根拠を記入しない。

```text
担当:
確認した回・コードの状態:
判定: OK / NG / BLOCKED
確認した要件ID・仕様項目:
根拠: ファイル、処理、テスト、実行結果など
指摘:
  - 指摘ID:
    関連する要件ID・仕様項目:
    実際の動作・問題:
    期待する動作:
    再現条件または根拠:
未確認・未実行の項目:
```

implementer は `判定` の代わりに `実装完了`、`修正完了`、または `BLOCKED` を記載し、対応した指摘 ID、変更ファイル、実行済み検証を付ける。implementer の自己報告だけでタスクを完了と判定しない。

NG は具体的な不適合、BLOCKED は判断不能である。OK は未確認事項がない対象コード状態に対してだけ記録できる。
