# 要件: ログイン・新規登録・ユーザー詳細画面

> この文書は後続のループエンジニアリングで実装対象とする要件である。この時点ではアプリのコード、DB、テストを変更しない。

## 目的

利用者がログイン ID とパスワードでログインできる状態を作る。アカウントを持たない、またはログインできなかった利用者は新規登録へ進み、登録またはログインに成功した利用者は自分のログイン ID を確認できる詳細画面へ進めるようにする。

## 対象範囲

- トップページのログイン画面
- ログイン ID とパスワードによるログイン
- 新規登録画面への遷移とアカウント登録
- ログイン失敗時の新規登録画面への遷移
- ログインまたは新規登録の成功後に表示する詳細画面

## 対象外

- パスワード再設定、メール認証、外部 ID プロバイダによる認証
- ログアウト、プロフィール編集、アカウント削除
- 管理者機能、複数組織・テナント機能
- デザイン詳細、文言・エラー表示の最終的な見た目

## 要件と受け入れ条件

### REQ-001: トップページにログイン画面を表示する

- 動作: トップページに、ログイン ID とパスワードを入力する欄、およびログインを実行する操作を表示する。新規登録へ進む操作も表示する。
- 受け入れ条件:
  - 未ログインの利用者がトップページを開くと、ログイン ID 入力欄とパスワード入力欄を確認できる。
  - パスワード入力欄の入力内容は画面上で平文表示されない。
  - 利用者が新規登録への操作を選ぶと、新規登録画面へ進める。

### REQ-002: 既存アカウントでログインする

- 動作: 登録済みのログイン ID と対応するパスワードでログインできる。
- 受け入れ条件:
  - 有効なログイン ID とパスワードを入力してログインすると、詳細画面へ遷移する。
  - 詳細画面には、ログインに成功したアカウントのログイン ID が表示される。
  - パスワードは詳細画面に表示されない。

### REQ-003: ログイン失敗時に新規登録へ誘導する

- 動作: ログイン ID またはパスワードが正しくなくログインできなかった利用者を、新規登録画面へ遷移させる。
- 受け入れ条件:
  - 未登録のログイン ID、または一致しないパスワードでログインを実行すると、詳細画面へは遷移しない。
  - ログインに失敗した利用者は、新規登録画面を表示できる。
  - ログイン失敗によって新しいアカウントが自動作成されない。

### REQ-004: 新規登録する

- 動作: 利用者がログイン ID とパスワードを入力して新しいアカウントを登録できる。
- 受け入れ条件:
  - 新規登録画面でログイン ID とパスワードを入力し、登録を実行できる。
  - 未使用のログイン ID で登録に成功すると、詳細画面へ遷移する。
  - 同じログイン ID を複数のアカウントに登録できない。
  - 必須入力が不足している、または重複したログイン ID の場合、アカウントを作成せず、利用者が登録できなかったことを確認できる。

### REQ-005: 登録・ログイン成功後に詳細画面を表示する

- 動作: ログインまたは新規登録に成功した利用者に、ログイン ID だけが識別情報として表示される詳細画面を表示する。
- 受け入れ条件:
  - ログイン成功時と新規登録成功時のどちらも詳細画面へ遷移する。
  - 詳細画面には、現在ログインしている利用者自身のログイン ID が表示される。
  - 詳細画面にパスワードや他の利用者のログイン ID は表示されない。

## 異常系・境界条件

- ログイン ID またはパスワードが空の場合は、ログイン成功・新規登録成功として扱わない。
- 存在しないログイン ID、一致しないパスワード、重複ログイン ID では、他人の詳細画面を表示しない。
- ログイン失敗時に入力済みログイン ID を新規登録画面へ引き継ぐかは未確定とする。

## 未確定事項

- ログイン ID の形式、文字数、使用可能文字、および大文字・小文字の扱い。
- パスワードの最低文字数・複雑性・確認入力の要否。
- 認証状態を維持する期間、詳細画面の直接アクセス時の扱い、ログアウトの導入時期。
- ログイン失敗時に表示するメッセージと、新規登録画面へ自動遷移させる具体的なタイミング。
- 詳細画面でログイン ID 以外の情報や操作を将来表示するかどうか。
